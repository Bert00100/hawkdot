# QA local — 20/09/2026

## Ambiente

API local em `localhost:3000`, health check 200 e PostgreSQL acessível.
O worker estava parado; foi iniciado com `hawkdot_worker_login`.
Os testes usaram `hawkdot_test`, separado do banco de uso local.
Alterações já existentes no frontend e no teste de ping foram preservadas.

## Defeitos corrigidos

- Checks acima de cinco segundos perdiam o resultado por expiração da transação Prisma. Reproduzido com teste real de 5,2 segundos antes da correção. Rede agora roda fora das transações; execução, estado, incidentes e eventos são persistidos atomicamente, com RLS e bloqueio da linha do monitor.
- Resultado de monitor pausado/excluído durante o check era aplicado. Agora é descartado; resultados anteriores a uma checagem já persistida também não sobrescrevem o estado.
- Polling do worker encerrava em falhas transitórias. Agora tenta novamente e limita os checks concorrentes ao tamanho do pool, drenando lotes cheios sem espera adicional.
- Telas não atualizavam resultados automaticamente. Agora atualizam a cada 15 segundos com aba visível, cancelam respostas obsoletas e preservam a edição em andamento.
- Configurações retornadas com campos opcionais nulos eram reenviadas ao DTO de escrita e impediam salvar. O formulário envia apenas os campos editáveis compatíveis.
- Dashboard exibia histórico simulado e uptime calculado pelo estado atual. Agora mostra dados atuais reais e estados sem dados explícitos.
- Busca só filtrava a página carregada. Agora `q` filtra no banco antes da paginação; seleção de recursos também permite navegar além dos primeiros 100.
- Erros de ações, carregamento e validação podiam ficar invisíveis. Há mensagens e recuperação; sessão expirada redireciona ao login.
- Campo de avisos SSL removia a vírgula durante a digitação. Texto de edição agora é preservado e validado.
- CSS escondia o botão de excluir recursos no celular. Ações continuam acessíveis; busca mobile ocupa uma linha inteira e modais mantêm foco e suportam Escape.
- Cadastrar recurso não inicia checks. A interface agora orienta criar um monitor após o cadastro.

## Validação

- `npm test -- --runInBand`: 71 suítes, 433 testes aprovados, incluindo permissões/RLS, reservas concorrentes, incidentes, HTTP, SSL e regressões adicionadas.
- `npm run test:e2e`: seis cenários aprovados em Chromium desktop e emulação mobile. Cadastro/login/logout, recurso HTTPS, check real de seis segundos, atualização automática, edição preservada, pausa/reativação, exclusão, SSL, erros, sessão expirada, busca, filtros e paginação.
- Após ajuste final da largura da busca mobile, os dois cenários de busca foram repetidos e passaram.
- Build de produção isolado em `.next-build` aprovado; TypeScript sem erros.
- ESLint sem erros, com seis avisos preexistentes em testes.

## Limites

Não foi implementado uptime histórico, conforme decisão de escopo. Testes de navegador cobrem Chromium, não Firefox/WebKit. O health check valida API e banco, não a execução do worker; manter `npm run worker` ativo é necessário. Jest ainda avisa sobre handles abertos ao encerrar a suíte, embora termine com código zero. Nenhum deploy ou commit foi feito.

As operações de limpeza do E2E removem apenas as contas e organizações criadas pela própria execução de QA; os testes Jest usam a limpeza do banco de testes já existente no projeto.
